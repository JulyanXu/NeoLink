# NeoLink 企业 3D 图谱设计

日期：2026-05-15

## 背景

当前 `enterprise-map.html` 是 2D SVG 连线 + HTML 圆形节点的企业图谱，数据来自 `data/enterprise-map-db.js`。线上版本包含 22 家企业、32 条关系、4 个来源，重点是储能、动力、3C 电池制造商榜单。

用户希望把企业图谱重新设计成 3D 效果，并补全产业链信息。已确认的产品方向是：

- 选择“储能产业链全景”，不只展示电芯企业。
- 第一版覆盖核心产业链，约 80-120 个节点。
- 地域范围为“中国为主，全球补充”。
- 页面体验为“可操作仪表盘”：3D 图谱为主，右侧详情面板辅助查询。
- 实现路线为 3D 产业链分层网络。

## 目标

1. 把企业图谱从电芯榜单关系图升级为储能产业链全景图。
2. 使用 3D 视觉表达产业链层级、企业关系、海外连接和项目线索。
3. 补全电芯、材料、PCS/逆变器、系统集成、业主/电网、海外客户/项目方等节点。
4. 保持 NeoLink 当前静态站部署模式，不引入复杂构建链。
5. 所有强关系和关键指标保留来源、日期、口径或可信度说明。

## 非目标

- 第一版不做实时自动爬取和自动写库。
- 第一版不做企业关系编辑器。
- 第一版不表达未经证实的股权控制、供应链独供或客户绑定关系。
- 第一版不把所有新能源企业做成大而全数据库。
- 第一版不改首页、新闻页、MarketTrend 或企业图谱无关样式。

## 页面结构

`enterprise-map.html` 改为一个产业情报工作台：

- 顶部：页面标题、搜索框、主题切换、重置视角。
- 筛选栏：产业链层级、关系类型、地区、上市状态、风险/项目/海外关系开关。
- 主区域左侧：3D 图谱舞台，占桌面宽度约 65%-70%。
- 主区域右侧：节点详情面板，占桌面宽度约 30%-35%。
- 图谱角落：图例、视角控制、节点数量/边数量摘要。
- 移动端：默认简化图谱和详情优先布局，避免手机上强行渲染完整密集 3D 网络。

右侧详情面板按节点类型渲染：

- 企业节点：身份、主营、产业链角色、上市状态、地区、关键指标、项目、客户/合作、风险、新闻、来源。
- 产业链聚合节点：代表企业、关键指标、近期行情/政策影响、来源。
- 项目节点：地点、规模、状态、参与方、来源。
- 市场节点：国家/区域、需求线索、代表项目、关联中国企业、来源。

## 数据模型

继续使用 `data/enterprise-map-db.js` 作为静态数据源，但结构从 `companies + relationships` 升级为 `nodes + edges`。

```js
window.NeoLinkEnterpriseDB = {
  meta: {
    version,
    generated_at,
    scope,
    methodology,
  },
  sources: [],
  nodes: [],
  edges: [],
};
```

节点字段：

```js
{
  id: "catl",
  type: "company",
  name: "宁德时代",
  shortName: "CATL",
  role: "cell",
  country: "中国",
  region: "福建宁德",
  listing: "A+H上市",
  segments: ["storage", "power"],
  metrics: [],
  projects: [],
  news: [],
  risks: [],
  sourceIds: []
}
```

边字段：

```js
{
  id: "catl-sungrow-project",
  from: "catl",
  to: "sungrow",
  type: "project",
  label: "储能项目/系统协同",
  strength: 0.7,
  confidence: "medium",
  sourceIds: []
}
```

## 节点分类

第一版节点控制在 80-120 个，按以下角色组织：

- `material`：锂资源、正极、负极、隔膜、电解液、铜箔、铝箔等材料公司。
- `cell`：储能电芯、动力电池、消费电池公司。
- `bms`：BMS、电池管理、电池安全与监控相关公司。
- `pcs`：PCS、逆变器、电力电子公司。
- `integrator`：储能系统集成商、设备供应商。
- `owner`：央企能源集团、地方能源平台、项目业主。
- `grid`：电网、调度、输配电、电力设备相关主体。
- `market`：美国、欧洲、中东、澳洲、东南亚等海外市场节点。
- `project`：只保留高价值项目节点，避免项目数量淹没企业结构。
- `segment`：材料、电芯、系统集成、央企业主、海外 BESS 市场等聚合节点。

第一版重点企业池：

- 电芯：宁德时代、比亚迪、亿纬锂能、海辰储能、中创新航、瑞浦兰钧、远景动力、国轩高科、楚能新能源、鹏辉能源、LG新能源、三星SDI、SK On、松下。
- PCS/系统集成：阳光电源、华为数字能源、科华数能、上能电气、盛弘股份、南瑞继保、许继电气、海博思创、远景能源、天合储能。
- 材料：天齐锂业、赣锋锂业、华友钴业、容百科技、德方纳米、湖南裕能、恩捷股份、星源材质、新宙邦、天赐材料、贝特瑞、璞泰来、中伟股份。
- 业主/电网/央企：国家电网、南方电网、国家能源集团、华电、华能、大唐、三峡能源、中广核新能源、中国电建、中国能建。
- 海外补充：Tesla Energy、Fluence、Powin、NextEra、Meralco、Energy Vault、BayWa r.e. 等与中国供应链或公开项目线索相关的节点。

## 关系类型

第一版只表达可解释、可筛选的关系：

- `supply`：供应链关系，必须有公告、招标、新闻或公开报告支持。
- `customer`：客户/采购关系，必须有公开项目、框采、订单或公告支持。
- `project`：同一项目或同一招标/中标关系。
- `investment`：投资、合资、持股、产业合作，必须有公告或工商/交易所口径。
- `same_rank`：同一榜单或同一排名体系。
- `technology`：技术路线、产品平台或共同技术标签。
- `market`：海外市场连接，例如中国企业与某区域项目/客户/需求线索。

关系强度 `strength` 用于 3D 布局：

- 0.9-1.0：公告确认的客户、项目、股权或合资关系。
- 0.6-0.8：招标、中标、框采、公开合作或强项目共现。
- 0.3-0.5：同榜、同赛道、同技术路线。
- 0.1-0.2：弱线索或聚合节点连接。

## 信息来源口径

来源分级：

- S 级：官方公告、交易所披露、招标平台、企业公告、政府/监管文件。
- A 级：InfoLink、SNE Research、EVTank、CNESA、SMM、Mysteel、GGII 等专业源。
- B 级：行业媒体、财经媒体、公众号、海外产业媒体。

写入规则：

- 强关系必须至少有 S 级或 A 级来源；B 级只能作为线索或补充说明。
- 榜单和出货数据必须保留年份、指标、发布方和口径。
- 项目关系必须保留地点、规模、状态、参与主体和来源。
- 风险关系必须优先使用公告、监管、法院、消防、应急或交易所来源。
- 低置信关系写入节点详情的“线索”，不画成强边。

## 3D 视觉设计

技术方案：Three.js + 自写轻量力导向布局，不引入 React/Vite 构建链。

空间映射：

- X 轴：产业链层级，从材料 → 电芯 → BMS/PCS → 系统集成 → 业主/电网 → 海外市场。
- Y 轴：节点重要性，龙头、聚合节点和高影响项目更靠上、尺寸更大。
- Z 轴：地域和关系簇，中国主体靠近中间，海外补充节点后撤。

节点表现：

- 企业：球体。
- 产业链聚合节点：半透明环或较大的柔光节点。
- 项目：小方块或棱角节点。
- 市场：带边框的区域光点。
- 选中节点：发光、放大、邻居高亮、非邻居降透明。

边表现：

- 供应/客户：实线。
- 项目：高亮实线。
- 投资：双线或加粗线。
- 同榜/技术：虚线。
- 海外市场：弧线或浅色远端连接。

视觉风格保持 NeoLink 情报站属性：深浅主题兼容，克制、清晰、适合扫描，不做纯装饰大屏。

## 交互

第一版支持：

- 拖拽旋转视角。
- 滚轮缩放。
- 点击节点选中。
- 搜索企业、角色、国家、项目关键词并定位节点。
- 按产业链层级、关系类型、地区、上市状态筛选。
- 一键只看邻居关系。
- 一键重置视角。
- 右侧详情随选中节点更新。

第一版不支持：

- 用户直接编辑节点和关系。
- 自动保存布局。
- 复杂时间轴动画。
- 实时数据订阅。

## 移动端与降级

移动端策略：

- 默认使用简化节点数量和更少边。
- 详情面板移动到图谱下方。
- 筛选器改为横向滚动。
- 若设备性能较弱，显示关系摘要和列表优先。

WebGL 降级：

- 检测 WebGL 不可用时显示 2D/列表 fallback。
- fallback 至少支持搜索、筛选、详情查看。
- 页面不得出现空白 canvas。

## 实现边界

预计改动文件：

- `enterprise-map.html`
- `enterprise-map.js`
- `data/enterprise-map-db.js`
- `styles.css`
- 必要时更新 `README.md` 或 `docs/hermes-content-ops.md` 中企业图谱说明。

不改动：

- 首页内容流。
- MarketTrend bundle。
- 新闻详情页。
- 现有内容 feed。

## 验证计划

开发完成后必须执行：

```bash
node --check data/enterprise-map-db.js
node --check enterprise-map.js
node --check script.js
node --check news-more.js
node --check article.js
```

浏览器验证：

- 本地 HTTP 服务打开 `/enterprise-map.html`。
- 桌面视口检查 canvas 非空、节点可见、边可见。
- 点击节点后右侧详情正确变化。
- 搜索企业后选中并定位节点。
- 筛选产业链层级和关系类型后节点/边数量变化合理。
- 移动端视口无横向溢出，详情可读。
- WebGL 不可用时显示 fallback。

数据验证：

- 节点数在 80-120 范围内。
- 核心角色至少覆盖材料、电芯、PCS/逆变器、系统集成、业主/电网、海外市场。
- 强关系都有 `sourceIds`。
- 核心企业不是孤立节点。
- sources 中没有空 URL、空发布方或空口径。

## 风险与取舍

- 3D 图谱容易牺牲可读性，所以第一版必须保留强筛选和详情面板。
- 企业关系准确性比节点数量更重要，未证实关系只能作为线索展示。
- Three.js CDN 依赖需要稳定可访问；如需离线部署，应把库文件本地化。
- 80-120 节点是第一版性能边界，后续扩展到 200+ 节点前需要优化渲染和布局。
- 移动端不追求完整 3D 密度，优先保证可查、可读、不卡顿。

## 通过标准

第一版完成后应满足：

- 用户打开企业图谱第一屏能看出“储能产业链全景”，不是单纯电池企业排名。
- 用户能通过 3D 图谱理解材料、电芯、系统集成、业主/电网、海外市场之间的关系。
- 用户点击任意核心企业都能看到可信来源支撑的公司、项目、指标和风险摘要。
- 用户可以通过筛选快速只看某一层级、某一关系或某一地区。
- 页面在桌面浏览器稳定运行，移动端有可用降级体验。
